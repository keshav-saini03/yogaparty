<task type="checkpoint:human-action" gate="blocking">
  <name>Task 3: Link Vercel project, configure env vars, and trigger first deploy</name>
  <what-built>
The GitHub repo exists with the scaffold pushed (Task 2). This checkpoint links Vercel to that repo and configures the three required env vars via the Vercel dashboard. Per RESEARCH.md Topic 5, env vars go through the Vercel UI (not committed) to prevent leaks.

Vercel CLI exists, but on first-time use against a new project it still requires browser auth and project import — the dashboard is the simpler path for a 5-minute one-time operation. Subsequent deploys are fully automatic via `git push`.
  </what-built>
  <how-to-verify>
**Step 1 — Sign in to Vercel:**

1. Open https://vercel.com/new
2. Sign in with GitHub (the same account that owns the `yogaparty` repo).
3. Authorize Vercel to access the repo if prompted (grant access only to the `yogaparty` repo, not all repos).

**Step 2 — Import the project:**

1. From the Vercel "New Project" page, find the `yogaparty` repo and click **Import**.
2. Framework Preset: **Next.js** (auto-detected — do not change).
3. Root Directory: `./` (auto — do not change).
4. Build Command: leave blank (Vercel defaults to `next build`).
5. Output Directory: leave blank (Vercel defaults).
6. Install Command: leave blank.

**Step 3 — Configure environment variables (in the same import screen):**

Expand **Environment Variables** and add THREE variables:

| Name | Value | Environments |
|---|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` | `https://YOUR_PROJECT.supabase.co` (from Plan 02 Task 1) | Production, Preview, Development |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | (anon key from Plan 02 Task 1) | Production, Preview, Development |
| `SUPABASE_SERVICE_ROLE_KEY` | (service role key from Plan 02 Task 1) | **Production ONLY** |

**Critical (per RESEARCH.md Topic 5 + Pitfall 2):**
- The third variable must be `SUPABASE_SERVICE_ROLE_KEY` — **NOT** `NEXT_PUBLIC_SUPABASE_SERVICE_ROLE_KEY`. If you accidentally prefix it, Vercel will expose the service role key to every browser session, which would be a credential breach. Rotate the key in Supabase if this happens.
- `SUPABASE_SERVICE_ROLE_KEY` should NOT be checked for Preview or Development. Preview deploys for pull request branches don't need the service role key, and reducing surface area is good hygiene.

**Step 4 — Deploy:**

Click **Deploy**. Vercel runs the first build (~1–2 minutes). You should see:
- Building ✓
- Deployment Ready ✓

Capture the production URL (looks like `https://yogaparty-<hash>.vercel.app` or `https://yogaparty.vercel.app`).

**Step 5 — Smoke-test the production URL:**

```bash
curl -sf https://yogaparty.vercel.app | grep -q "YogaParty"
```

Or open the URL in a browser. The placeholder copy "YogaParty — coming soon 🧘" must render.

**Step 6 — Verify the geolocation middleware is running:**

```bash
curl -sI https://<your-vercel-url>/ | grep -i "x-geo"
```

You should see `x-geo-city` and `x-geo-country` response headers. The values may be your real city/country (since you're hitting Vercel's edge). Locally these are empty — that's expected per RESEARCH.md Pitfall 5.
